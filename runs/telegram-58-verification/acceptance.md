## 一个不是 bug 的观察

真机上卡片正文是**英文**，因为宿主界面语言解析为 `en`（三层：config/settings/mirror 均未显式设中文）。
代码验证：`t()` 默认语言是 `zh`，`setImHostLanguage('zh')` 后输出中文。
**这是环境配置差异，不是移植缺陷**——同一份代码在不同语言设置下输出不同语言，符合设计。

## 第二轮真机验证（补充）

又试了一轮，把点击精度也校准了（按截图中心点换算，误差从 31px 降到 0），结果：

| 尝试 | 结果 |
| --- | --- |
| 用 Bot API 发 `/status` | ❌ bot 自己发的命令不会被 Telegram 回传，那两条只是普通回复，**不触发卡片路径** |
| GUI 手动输入 `/status` | ✅ 卡片正常生成（`25-status-card-on-5.8-user-sent.png`） |
| 点击新卡的「🔄 刷新」 | ❌ 按钮有按下高亮，但卡片不重绘，随后出现红色错误反应标记 |
| 服务端日志 | ❌ 89 行日志里**没有任何 callback 记录**，说明回调请求根本没到服务端 |

### 判断
Telegram Desktop 在无头/GUI 自动化环境下，点击内联键盘按钮后**没有把 callback_query 发出去**（本地只有视觉高亮 + 失败标记），
所以这条路无法用来验收按钮交互。

另有一个环境事实需要记住：**bot 自己发出的消息不会回到 bot**，所以不能用 Bot API 自发命令来生成卡片，
必须由真人/模拟真人的输入触发。

### 结论
按钮交互**始终没有真机证据**，只有 186 例单测。这一点在交付时必须说明，不能含糊成"已验证"。

## 第三轮尝试：找到了前两次失败的关键原因

**前两轮点击不动的真正原因是卡片跨进程失效，不是点击不准。**

诊断方法：`systemctl --user show dsh-lab-web -p ActiveEnterTimestamp` 对比卡片上的时间戳。

实测：
- 卡片发出：19:08
- 服务启动：19:13:39（中途重启过）

卡片 nonce 只活在发出它的那个进程里，重启后注册表是空的，所以任何点击都无效——
这解释了为什么按钮有按下高亮、却没有任何 callback 到达服务端。

**修正做法**：改成「先确认服务启动时间 → 再发卡 → 立刻点击」。用当前进程（19:13:39 启动）
在 19:18 发出了新卡，但**点击仍未成功**（callback 依然没有到达服务端，日志无记录）。

本轮还试了 ydotool（Wayland 原生输入模拟，绕过 CUA 的坐标换算）：
- `ydotool click 0x40` 是错的（0x40 = 只按下不松开），正确是 `0x00`
- 改正后点击到底了，但结果相同

### 最终结论
在 wings-gpd 的 KDE Wayland + Telegram Desktop 7.3.3 环境下，通过自动化手段点击内联键盘按钮
**无法产生 callback_query**。三轮尝试覆盖了 CUA 点击、精确坐标换算、ydotool 三种方式。

按钮交互因此**只能靠单测覆盖（186 例）**，没有真机证据。这一条必须在交付说明里讲清楚。

### 可复现的诊断命令
```bash
systemctl --user show dsh-lab-web -p ActiveEnterTimestamp --value   # 服务启动时刻
# 与卡片上的时间戳对比；服务晚于卡片 = 卡片已失效
```

## 第四轮：定位到根本原因（这条最有价值）

用**一个不依赖本项目的对照实验**证明了问题不在代码：

1. 停掉 dsh-im 服务（这样没有任何进程会消费回调）
2. 用 Bot API 发一条带固定按钮的消息：`callback_data = "TESTCB1"`
3. 点击它，然后直接调 `getUpdates` 看 Telegram 有没有把回调发出来

**结果：`getUpdates` 返回 0 条更新。** 也就是说连 Telegram 客户端自己都没发这个 callback_query。

对照组进一步缩小范围：
- 用 ydotool 点击**聊天列表里的另一个会话**，也没有任何反应 → **ydotool 在 Wayland 上完全不生效**
- CUA 的点击能生效（能切会话、能聚焦输入框），但落到内联键盘按钮上时只有视觉高亮、不发回调

### 环境层面的结论
| 手段 | 能否点击 | 能否触发卡片回调 |
| --- | --- | --- |
| CUA（computer-use） | 能，但坐标有偏差 | ❌ 只有高亮 |
| ydotool | **完全无效**（连切会话都不行） | ❌ |
| Bot API 自发命令 | — | ❌ bot 自己的消息不会回传 |

三种手段都试过，**在这台机器上无法产生 callback_query**。这是环境限制，不是产品缺陷。

也就是说：按钮交互缺真机证据这件事，**到此为止，已经证明是环境的天花板**，不是没试够。
