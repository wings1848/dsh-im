# P1-3：`/status` 状态卡（轻量档）

## 一句话
`/status` 从一段文字变成可操作卡片：保留每一条状态信息，再给「刷新 / 菜单 / 会话 / 工作区 / 模型 / 预设 / 帮助」入口。

## 验收表

| # | 标准 | 判定命令 | 实测 |
| --- | --- | --- | --- |
| A1 | 有键盘渠道 `/status` 出卡，正文保留全部状态行 | `node --test test/channels/telegram/status-card.test.mjs` | ✅ 18/18 |
| A2 | 「刷新」重新读状态并**原地重绘**同一消息 | 同上 | ✅ |
| A3 | 刷新失败 → 不重绘、提示失败、按钮仍可点 | 同上 | ✅ |
| A4 | 入口按钮等价于手打命令，且不改动状态卡 | 同上 | ✅ |
| A5 | 无键盘 / `statusCard: null` / 卡片被拒 → 原文字状态 | 同上 | ✅ |
| A6 | 过期卡、跨聊天、被替代的卡都不能驱动 | 同上 | ✅ |
| A7 | 并发双击刷新只读一次 | 同上 | ✅ |
| A8 | 回调只带 `t1\|nonce\|动作`，≤64 字节，不含路径/会话 ID | 同上 | ✅ |
| A9 | 全量回归 + 打包 | `npm run check` | ✅ 4615 例 0 fail |

## 不变量
- **`/status` 文字输出不变**：`runStatusCommand` 只是多返回一个 `statusSnapshot` 字段，
  `message` 逐字未改；所有无卡渠道与降级路径仍发那段文字。
- 卡片不自动刷新：状态是快照，过期状态比明显过期的状态更危险，所以刷新是显式按钮。
- 工作区路径在卡片里截成最后一段，避免长路径撑破布局。

## 设计取舍
- 预设按钮只在 Host 确实报告了预设时出现（没有预设时按了也没意义）。
- 「刷新」由卡片自己处理（读 + 重绘），其余按钮都重放已有命令，卡片不发明新行为。
