# P1-6：审批卡长参数折叠（轻量档）

## 一句话
工具参数很长时，审批卡折成摘要 + 「📄 查看完整参数」按钮；点按钮发全文，**看完再决定**。

## 为什么不能直接截断
当前行为是：参数超过 6000 字符 → `harnessApprovalText` 返回 null → 审批被**安全拒绝**。
如果为了「出得了卡」而把参数截断展示，用户就会在**没看过完整内容**的情况下批准一条 shell 命令。
那是把可用性问题换成安全问题。所以折叠必须保证全文**随时可达**。

## 验收表

| # | 标准 | 判定命令 | 实测 |
| --- | --- | --- | --- |
| A1 | 短正文不折叠 | `node --test test/channels/telegram/approval-card.test.mjs` | ✅ 24/24 |
| A2 | 长参数折叠后有「其余 N 行已折叠」+ 提示 | 同上 | ✅ |
| A3 | 「原因：」行在折叠后仍保留 | 同上 | ✅ |
| A4 | 全文逐字保留（`fullText`），供按钮下发 | 同上 | ✅ |
| A5 | 认不出的正文**不**盲折，原样返回让上层走尺寸检查 | 同上 | ✅ |
| A6 | 点「查看完整参数」发全文、**不认领卡片、不提交审批** | 同上（端到端） | ✅ |
| A7 | 看完详情后审批仍可正常提交 | 同上 | ✅ |
| A8 | 全量回归 + 打包 | `npm run check` | ✅ 4620 例 0 fail |

## 不变量
- 折叠是**纯展示**：`fullText` 是原始 body，一字不改。
- 「查看完整参数」不 claim nonce，所以读详情不会消耗唯一一次决定机会。
- 只折叠「操作参数」块，工具名与原因保持可见。
- 卡片仍受 4096 字符上限保护：折完还超长就走原文字路径（分片发送）。

## 阈值
`TELEGRAM_APPROVAL_FOLD_ARGUMENTS_CHARS = 900`（参数超过即折）、
`TELEGRAM_APPROVAL_FOLD_LINES = 12`（保留前 12 行）。
